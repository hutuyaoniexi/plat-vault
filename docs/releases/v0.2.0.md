# PlatVault v0.2.0

## 版本定位

PlatVault v0.2.0 是 Chrome Manifest V3 扩展，提供两个相互独立的功能：仓库估价与核桃分析。首页先展示“仓库估价”，其次是“核桃分析”；点击功能按钮后处理已添加的截图。

## 功能与流程

### 仓库估价

用户拖入或粘贴仓库截图后，可查看缩略图、预览原图或移除截图，再启动仓库估价。系统在本地运行 OCR，匹配 WFM 商品目录，并查询可精确匹配商品的订单。结果展示商品名称、最低游戏内卖价、参考价、杜卡德、杜卡德/白金建议和 WFM 商品页链接。用户可应用或重置 D/P 阈值，并切换结果排序。

模糊匹配仅用于找候选商品；只有精确匹配且不依赖 Rank 等规格的商品才会自动查价。无法匹配或不支持自动估价的物品仍显示在结果中，但不会生成商品跳转链接或价格。

### 核桃分析

点击“核桃分析”后，系统直接对当前截图运行本地 OCR，无需确认 OCR 结果。识别文本中的纪元和编号；数量从截图左上角的 `×N` 标记解析。相同名称会跨截图合并数量。精炼等级不参与识别或统计。

随后加载 WFCD 的核桃奖励数据和 WFM 商品目录、订单价格，并对每种核桃给出一个互斥建议：

1. **WFM 卖**：核桃参考价高于最佳达标 Rare 奖励估值加决策缓冲。
2. **光辉组**：至少有一个 Rare 奖励价格达到金部件阈值。
3. **刷 Forma**：没有更高优先级建议，且 Forma Blueprint 位于 Common 或 Uncommon 档；分别建议完整或无暇精炼。
4. **批量卖核桃**：以上条件均不满足。

部件估值取 WFM 参考价与“杜卡德 ÷ D/P”的较高值。默认 D/P 为 8、金部件阈值为 20P、WFM 决策缓冲为 15%。设置只在当前页面状态中生效，不写入浏览器本地存储；应用或重置设置会清除旧结果并重新分析。

没有对应奖励数据，或核桃的 Rare 奖励缺少有效价格时，该核桃列入“待核对核桃”，不生成分类建议。没有结果的分类卡片不显示。批量卖、刷 Forma 和光辉组卡片可分别复制，复制内容仅含“核桃、数量”，顺序与卡片列表一致。

## 图片与数据规则

- 仅支持拖入或粘贴 PNG、JPEG、WebP 图片，不提供点击选择文件入口。
- 单张图片最大 20 MB、分辨率最大 1600 万像素；限制在浏览器解码前检查。
- 图片解码、缩放和 OCR 均在浏览器本地完成，截图不会上传到服务端。
- 仓库估价的 WFM 商品目录缓存在 `chrome.storage.local` 24 小时；核桃分析设置不持久化。核桃奖励数据在当前页面会话中缓存。
- WFM 请求经队列控制，间隔至少 350 毫秒；请求超时为 12 秒，最多重试 3 次，`Retry-After` 等待最多 30 秒。同一商品的并发订单查询会合并。

## 已知限制

- OCR 依赖截图清晰度和游戏界面中的可读名称；数量标记识别可能受布局和 OCR 质量影响。分析结果应结合“待核对核桃”及截图人工检查。
- 核桃奖励和市场价格依赖外部数据源及网络。奖励记录缺失、目录中没有对应商品或没有有效游戏内卖单时，相关核桃可能进入待核对列表。
- WFM 功能为只读查询，不支持登录、创建或修改订单、交易或自动组队。
- 不提供云端同步、账号体系或历史价格分析。

## 技术说明

- 前端使用 React、TypeScript、Vite，按 Chrome Manifest V3 扩展运行。
- OCR 使用 Tesseract.js Worker 和本地简体中文语言数据。
- WFM v2 客户端负责商品目录、订单查询、目录缓存、限流、并发去重、超时及重试。
- 核桃分析使用 WFCD 公共遗物数据，并通过 WFM 目录和订单数据计算奖励及核桃参考价格。
